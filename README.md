# Daily Backend Labs

One backend engineering challenge every morning, generated by the Gemini API and
opened as a pull request. I solve it, write up what I learned, and merge.

**The bot writes the question. I write the answer.**

That split is deliberate. The generated PR is authored by `github-actions[bot]`
and counts toward nobody's contribution graph. The only commits that count here
are the solutions — which is right, because those are the ones that represent
work someone actually did.

## The week

| Day | Topic |
| --- | --- |
| Monday | PostgreSQL |
| Tuesday | TypeScript and Node.js |
| Wednesday | Redis and caching |
| Thursday | System design |
| Friday | AWS and cloud infrastructure |
| Saturday | Data structures and algorithms |
| Sunday | Distributed systems |

Challenges are grounded in production situations rather than puzzles — *"this
invoices query got slow at 40 million rows"* rather than *"reverse a linked
list"*. Each one states its constraints, lists concrete deliverables, and ends
with a "going further" question that probes whether the solution is understood
or just copied.

The prompt explicitly forbids including the answer. Editable at
[`prompts/challenge.md`](prompts/challenge.md).

## Layout

```
challenges/2026-08-07.md      the question, plus my write-up
solutions/2026-08-07/         my actual work
prompts/challenge.md          the generation prompt
scripts/generate_challenge.py the generator
```

## Daily loop

```bash
gh pr checkout challenge/2026-08-07   # 1. take today's PR
                                      # 2. solve it in solutions/2026-08-07/
                                      # 3. fill in Approach / What I learned
gh pr merge --squash                  # 4. merge
```

Skipped a day? Leave the PR unmerged. An honest gap beats a fake square.

## Running it manually

```bash
export GEMINI_API_KEY=...

python scripts/generate_challenge.py                # today's topic
python scripts/generate_challenge.py --topic Kafka  # override
python scripts/generate_challenge.py --dry-run      # print, write nothing
python scripts/generate_challenge.py --list-models  # what your key supports
```

Standard library only — no dependencies to install or keep updated.

If the API returns a 404, the model id has been renamed or retired. Run
`--list-models` and set the `GEMINI_MODEL` repository variable to one of the
ids it prints.

## Setup

1. Get a key at [aistudio.google.com/apikey](https://aistudio.google.com/apikey)
2. **Settings → Secrets and variables → Actions → New repository secret**
   `GEMINI_API_KEY`
3. Optionally set a repository *variable* `GEMINI_MODEL` to pin a model
4. **Actions → Daily challenge → Run workflow** to test it without waiting for
   the 09:00 schedule

The schedule is `30 3 * * *` (03:30 UTC = 09:00 IST). GitHub's cron is
best-effort and can lag under load, so treat it as "some time in the morning".

## What this is not

It is not a contribution-graph generator. The scheduled job creates a question
and nothing else; if I don't solve it, no green square appears. The graph here
tracks days I actually did the work, which is the only version of it worth
having.
